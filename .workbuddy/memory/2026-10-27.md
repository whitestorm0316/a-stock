## 修复：前端 `echarts is not defined`（交易明细 / 回测双双失败）

**现象**：页面报「交易明细加载失败：echarts is not defined」「回测失败：echarts is not defined」。

**根因**：`app/index.html` 第 14 行用 `<script src="https://cdnjs.cloudflare.com/ajax/libs/echarts/5.5.0/echarts.min.js">`
从 cdnjs 拉 ECharts。国内网络下该 CDN 不可达 → 外链脚本静默失败 → 全局 `echarts`
不存在 → 任何 `echarts.init()` 调用都抛 ReferenceError，被各处 catch 后包装成上面两句提示。
**不是**业务逻辑/接口问题，后端接口本身正常。

**修复**（根因修复，非兜底）：
1. 下载 ECharts 5.5.0 到 `app/echarts.min.js`（1,029,203 B，尾部 `t.version="5.5.0"` 校验通过）。
   来源：npmmirror `https://registry.npmmirror.com/echarts/5.5.0/files/dist/echarts.min.js`（国内可达）。
2. `index.html` 改为同源 `<script src="/static/echarts.min.js">`。
   静态根就是 `app/`（`server.py` 的 `APP = dirname(abspath(__file__))`，`/static/x` → `APP/x`），
   `_STATIC_CTYPES[".js"]` 已映射 `application/javascript; charset=utf-8`，无需改 server.py。

**为什么不需要重启**：只动了 `index.html` + 新增静态文件，`_serve_file` 每次按 (name, mtime)
现读现缓存，静态目录不做索引缓存；`_send` 带 `Cache-Control: no-store`，浏览器也不会拿旧页。

**验证**：
- `curl /static/echarts.min.js` → 200，Content-Type 正确，Content-Length 1029203。
- jsdom `JSDOM.fromURL(8770, {resources:'usable'})` → 190ms 内 `window.echarts.version === "5.5.0"`，外链仅有 `/static/echarts.min.js`。
- `bash tests/run.sh trades` 119/119、`cap` 50/50 通过（测试本就 mock `w.echarts`，不受影响）。

**遗留/注意**：
- `scripts/report_template.html`、`report_v2_template.html`、`v3b_report_template.html` 三个
  **独立 HTML 报告模板**仍用 jsdelivr CDN。它们是脱离服务单独打开/外发的文件，不能用 `/static/`；
  若要离线可看，需把 echarts 内联进模板（体积 +1MB），暂未改。
- 一次性验证脚本 `​.workbuddy/echarts_load_check.js` 保留未删（避免触发删除确认）。

## 新增功能：实盘「持仓盈亏」（第 7 个 Tab）

**需求**：用户要「添加一个持仓盈亏」，确认后选的是 **实盘持仓账本**（不是回测未平仓浮盈）。

**模型**：一条记录 = 一个**买入批次**（lot），同票可多条（各自成本/买入日），逐笔算、合计汇总。
不做「一码一条」是因为合并成本必须选口径（加权/先进先出），写死就没法解释。

**关键口径决策（最容易被改错的地方）**：
- 现价用 **未复权** `close_price_raw`（`self.px_raw`），**不是**回测用的复权 `close_price`。
  理由：用户填的成本是券商实际成交价，只有未复权价同尺度；复权价遇分红送转会凭空多算/少算盈亏。
  实测 `close_price_raw` 覆盖率 100%（NaN 率 0），最后一天与复权价相等（前复权锚定在最新日）。
- 今日盈亏 = 现价 / **上一有效**收盘 − 1（收盘→收盘）；**不能**用 `oret`（开盘→开盘、末日常 NaN）。
- 持有天数 = **自然日**（买入日 → 该票最新行情日），不做交易日历换算。
- 盈亏**绝不落盘**：每次请求现算。落盘只有用户输入 → `data/holdings.json`（原子写，同 user_presets）。
- 无行情批次（退市/ST 被面板剔除/代码打错）**保留并标灰**，不计入合计但要报 `n_noquote`+`noquote`，
  绝不悄悄丢行。⚠️ 面板本身已剔除 ST/次新，所以「查不到行情」不一定是代码错。
- `/api/holdings` 里**不要**用 `ENGINE.meta()["last_date"]`：meta() 每次重建全量票单+行业树。
  改取 `ENGINE.day_str[ENGINE.nd-1]`，接口耗时 4.9ms。

**改动文件**：
- `app/engine.py`：新增 `_norm_code()`（正则取 6 位，别用 `strip("sh")` —— 会吃掉结尾 H）、
  `_code_index()`（惰性、进程内缓存、同码撞车取行数多的）、`quotes(codes)`（返回 dict，查不到不出现）。
- `app/server.py`：`HOLDING_FILE`/`load_holdings`/`save_holdings`/`_new_hold_id`/`_hold_days`；
  三个接口 `GET /api/holdings`、`POST /api/holdings/save`、`POST /api/holdings/delete`。
  校验失败一律 `ok:false + msg`（**不用 error 键**，否则前端 api() 会 throw）。
- `app/index.html`：第 7 个 Tab + `#p-hold` + `.hform` 样式 + `runHoldings/renderHoldings/bindHold/hSave`。
  红涨绿跌沿用 `.pos`/`.neg`；金额用 `hYuan`（**负号在 ¥ 前**：`-¥218.00`，不是 `¥-218.00`）。
- `tests/test_hold.js`（新，31 项，离线内存账本桩）+ `tests/run.sh` 注册 `hold` 并纳入 `all`；
  `tests/test_trades.js` 的「Tab 总数 6 → 7」（加注释说明新增项）。
- `app/README.md`：功能页 6→7、新增「持仓盈亏」章节、接口表 3 行、测试表 + 文件树。

**验证**：13 个 jsdom 套件全绿（642 项）；真实页面 + 真接口跑录入→渲染→编辑→删除 14/14；
独立复算盈亏一致（000001: 11.47×1000 → +1470；600519: 1355.9 → -14410）。

**坑**：`python scripts/ctl.py restart` 起服务后，**后台任务一结束进程就被回收**
（本机 DETACHED_PROCESS 不生效）→ 必须用 `run_in_background` 的 Bash **前台 `exec`**
持有 `app/server.py 8770`。当前服务是 task `o3pn1U` 持有（PID 见 netstat）。

**遗留**：账本无「已实现盈亏/交易流水」概念，卖出只能删记录；也没有导入券商对账单。
需要的话下一步做「卖出结算 → 已实现盈亏」。

## 追加：持仓页改成「策略持仓（自动）+ 实盘账本（手动）」

**用户反馈**：「回测中还在当前持有的不就是当前持仓吗，怎么还要录入」「预计卖出日期也要显示出来」。
→ 之前只做了手动账本，漏了「回测里 `kind="holding"` 的头寸本来就是当前持仓」这件事。

**改动**
- `app/engine.py`：新增 `positions(mask, hold, plan)` 与 `_next_trade_day()`。
  复用 `simulate_hold` + `_open_positions`（**口径与 trades() 逐位一致**），但跳过
  rows/summary/yearly/hist → 1.4s（trades 6.3s）。补最新**复权**收盘价、`pnl_pct`、
  `day_chg`、`exit_est`。
- `app/server.py`：新增 `POST /api/positions`（**GET /api/holdings 保持不变**，
  这样 test_hold 的桩不用改）。`pending` 字段实测恒为 0：`ent==nd` 时 T+1 开盘价
  越界为 nan → 归 nobuy，进不了 holding。
- `app/index.html`：`runHoldings()` 并行拉两个接口（策略块失败只降级自己）；
  策略表 `.btgrid`/`#p-tbl`/`th.pts`，**刻意不复用 `.mgrid`/`.ts`** —— test_hold 按
  `#p-hold .mgrid .mc .v` 取第一张卡，共用类名会串味。手动账本收进 `details.hfold` 默认收起。
- `tests/test_pos.js`（31 项，已接入 `run.sh pos` 与 `all`）+ README 同步。

**口径纪律**：策略持仓用**复权**价（与回测 buy 同尺度）且**只有收益率没有金额**；
手动账本用**未复权**价且有金额。两块合计**不能相加**，两处注释与 README 都写死了。

**预计卖出日** = 最新交易日 + (`left_days`+1) 个**工作日**。本地 `calendar.json`
末日就是面板末日，没有未来日历，法定节假日扣不掉 → 一律叫「预计」，精确值给「还需 N 个交易日」。

**验证**：真实接口 313 笔 / 67 只（默认参数），`positions` 1.4~2.0s、`holdings` 2ms；
真实页面集成 22/22；14 个 jsdom 套件全绿（675 项，含新增 31）。
**坑**：`tests/run.sh` 靠 `grep -oE '[0-9]+/[0-9]+'` 解析，测试**必须输出 N/M**，
写成「31 项」会被判「未能解析结果」（首次踩到）。
